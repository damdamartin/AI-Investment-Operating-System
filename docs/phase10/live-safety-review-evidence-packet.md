## Purpose

This document is the sanitized, human-facing evidence packet/checklist for
`LCB-007` (Kill-Switch and Rollback Evidence, Live Context) and `LCB-008`
(Real Broker Write Adapter Review Evidence), per the "Live-safety/review
packet" row of `docs/phase10/human-blocker-evidence-workbook.md`'s
"Evidence Packet Groups" table. It tells the two human owners of these
blockers — an **engineering safety reviewer** and an **independent senior
reviewer** — exactly what to record.

> **This packet is not live-trading authorization.** It does not resolve
> `LCB-007` or `LCB-008`. It does not approve a future write-adapter
> implementation on a human's behalf. Only a human editing
> `docs/phase7/live-capable-blocker-register.md` directly, following that
> file's own rules, can ever change either blocker's status in that
> register.

## Sanitization Rules (Restated)

Per `docs/phase10/human-blocker-evidence-workbook.md`, "Sanitization
Rules", this packet — and any evidence a human records against it — must
never include:

- API keys, client secrets, tokens, passwords, certificate material
- account numbers, raw broker payloads, raw headers
- local receipt contents (`tmp/phase5/*`), balances, holdings quantities
- personally identifying contract text

Only summaries, citations, masked references, reviewer names/roles,
review dates, decisions, limitations, and expiration dates belong here.

## Optional Machine-Checkable Validator

An optional pure validator/checklist for this packet's shape exists at
`src/application/live-readiness/live-safety-review-evidence-packet.ts`
(`reviewLiveSafetyReviewEvidencePacket`, plus the two per-blocker
functions `reviewLiveSafetyReviewLcb007Record` and
`reviewLiveSafetyReviewLcb008Record`). It is a pure function: no network
code, no filesystem access, no broker client, no side effects. It checks
that:

- every required field above is present and non-placeholder
- every free-text field is scanned for secret-like, account-identifier-like,
  raw-payload-like, or raw-header-like content, and for the literal word
  "resolved" (defense in depth on top of the register file's own rule)
- the `decision` field is one of exactly the five workbook-defined values
  (`LIVE_SAFETY_REVIEW_DECISIONS`) — `"RESOLVED"` is not a member of that
  type and cannot be produced by this module under any input
- `LCB-008`'s `adapterExistsYet` is strictly `false`
- a `HUMAN_REVIEWED_*` decision for `LCB-007` requires all seven rollback
  rehearsal steps completed
- `liveBrokerWriteAllowed` and `blockerRegisterResolutionAllowed` are
  hardcoded `false` literals in every code path, never computed from input

This validator does not, and cannot, mark `LCB-007` or `LCB-008`
`RESOLVED`. It does not decide whether the evidence is sufficient — that
judgment belongs entirely to the named human reviewers. See
`tests/application/live-safety-review-evidence-packet.test.ts` for the
full test suite proving these properties, including tests that a
deliberately tampered `"RESOLVED"` decision value (via an unsafe
type-cast) and a claimed-existing write adapter are both rejected, never
silently accepted.

## What This Packet Does Not Do

- It does not resolve `LCB-007` or `LCB-008`. Every field above defaults
  to incomplete until a human fills it in.
- It does not implement, call, or simulate a real Toss API call.
- It does not implement a callable broker-write adapter.
- It does not perform the independent code review that `LCB-008`
  requires — it only records that review's prerequisites.
- It does not read, print, or reference `.env`, `tmp/phase5`, local
  receipts, secrets, account identifiers, or raw broker payloads.
- It does not treat AI-assisted drafting of this checklist's structure as
  a substitute for human review, human sign-off, or human judgment.
